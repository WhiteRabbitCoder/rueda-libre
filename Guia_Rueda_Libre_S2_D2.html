De CSS propio a Bootstrap

Esta guía te acompaña para transformar Rueda Libre v1.5 en v2.0-beta. Partimos de un sitio que ya funciona con HTML, CSS, Flexbox y Grid. Hoy vamos a cambiar cómo se distribuye el contenido, conservar sus datos y comprobar que el formulario sigue validando igual.

Qué debes tener abierto

Extrae Rueda_Libre_Base_S2_D1.zip y abre rueda-libre-v1.5 en VS Code. Abre index.html con Live Server. Deja también el navegador y sus herramientas de desarrollo a mano. Necesitarás internet para cargar Bootstrap desde el CDN; las ilustraciones del proyecto son locales.

Cómo trabajar con esta guía

Lee la explicación, realiza el cambio en el archivo indicado y comprueba el resultado antes de seguir. Los bloques con comentarios como «conserva aquí los demás campos» muestran dónde va tu contenido existente; ese comentario no reemplaza el contenido. No borres campos, textos o imágenes para que el ejemplo se parezca más al bloque.

Comprueba la base

Navega desde cada página hacia las otras dos. En inicio deben aparecer siete modelos, incluido Tándem. En reservas, prueba enviar el formulario vacío: el navegador debe señalar un campo obligatorio. Reduce la ventana a 360 px y revisa que el documento no se desplace horizontalmente.

Lo que ya sabes y vas a reutilizar

HTML define el significado del contenido: nav sigue siendo navegación y article sigue siendo una unidad con sentido propio. CSS define su presentación. Flexbox organiza elementos en una dirección; Grid permite definir filas y columnas. Bootstrap aplica reglas CSS ya escritas a través de clases. No cambia el significado de las etiquetas.

<!-- Una etiqueta puede tener varias clases separadas por espacios. -->
<article class="tarjeta bici">
  <h3>Urbana Clásica</h3>
</article>

tarjeta y bici son nombres que definimos en nuestra hoja CSS. En cambio, col-sm-6 es un nombre definido por Bootstrap. Poner una clase en el HTML solo tendrá efecto si se carga la hoja que contiene su regla.

Las imágenes SVG del ejemplo son ilustraciones para practicar rutas y diseño. Si las cambias por fotografías, revisa el nombre del archivo, las mayúsculas, su extensión y el texto alternativo.

Guarda un punto de partida

Antes de migrar, guarda la versión actual. Así podrás consultar qué cambió y recuperar una referencia sin mantener dos sitios completos dentro del mismo proyecto.

Si la carpeta todavía no tiene Git

git init
git add .
git commit -m "Base Rueda Libre v1.5"
git branch -M main
git tag v1.5-base

git init inicia el repositorio local. git add prepara los archivos. git commit guarda una versión. git branch nombra la rama principal. La etiqueta v1.5-base señala el punto anterior a Bootstrap. Si ya tienes un repositorio, conserva su historial: omite git init y crea el commit de referencia solo si hay cambios pendientes.

Registra una medición que puedas repetir

Abre css/styles.css y anota el número total de líneas antes de cambiarlo. En VS Code, Ctrl + Fin lleva a la última línea y la barra de estado muestra su número. Decide desde ahora contar todas las líneas, incluidas las vacías y los comentarios, y usa el mismo criterio al terminar.

# Consultar después el CSS inicial sin modificar tus archivos
git show v1.5-base:css/styles.css

Para la comparación de la flota, cuenta por separado las declaraciones de distribución: display, grid-template-columns y gap del bloque .flota. No confundas ese conteo con las líneas totales de la hoja ni con el número de clases de HTML.

Si recibiste esta base y no construiste su versión original, escribe «tiempo de construcción original no medido». Sí puedes medir cuánto tardas hoy en reconstruir la flota. Bootstrap puede reducir tu CSS propio y aumentar las clases del HTML; registra ambas cosas.

Antes de continuar

Confirma que git status indica un árbol limpio después del commit. No cambies de rama ni restaures archivos para consultar el pasado: git show permite leerlos sin tocar el trabajo actual.

FUNDAMENTO 01

Entiende qué aporta un framework

Imagina que quieres separar dos elementos, centrar un título y organizar cuatro bloques. Con CSS propio escribes las reglas y decides sus valores. Con un framework eliges entre reglas disponibles. Sigues tomando decisiones de diseño: el framework no elige por ti qué debe ser importante ni cómo se entiende el contenido.

/* Una regla escrita por nosotros */
.separacion { padding: 1rem; }

<!-- Una utilidad equivalente de Bootstrap con su escala por defecto -->
<div class="p-3">Contenido con espacio interior</div>

La clase p-3 representa padding de 1rem en los cuatro lados con la configuración predeterminada de Bootstrap. El 3 es una posición en una escala, no tres píxeles. Usar una escala ayuda a repetir espacios coherentes.

HerramientaQué resuelveQué sigues decidiendo
GrillaAnchos y distribución responsiveCuántas columnas necesita cada sección
UtilidadesAjustes concretos de CSSEspacio, alineación y jerarquía
ComponentesPatrones como navbar o modalContenido, comportamiento y personalización

Por qué no borramos todo el CSS

Los colores de Rueda Libre, sus fuentes, el aspecto de sus tablas y los estados de foco pertenecen a su identidad. La migración de hoy mueve la distribución hacia Bootstrap. Mantendremos reglas de marca y controles que ya funcionan.

Qué es un CDN

Es un servicio que entrega archivos desde una red de servidores. Al usar una URL de CDN, el navegador descarga la hoja CSS o el bundle de JavaScript. Si no hay conexión, ese recurso puede no estar disponible. Fijamos la versión 5.3.8 para que todos practiquemos con los mismos archivos, tal como aparece en el material de la clase.

La grilla y las utilidades funcionan con el CSS de Bootstrap. El bundle se carga porque lo pide el reto y quedará listo para los componentes del día 3; no es lo que activa las columnas.
FUNDAMENTO 02

Lee la grilla de doce partes

La grilla estándar de Bootstrap se organiza con un contenedor, una fila y columnas. Aunque su nombre se traduzca como cuadrícula, esta grilla usa Flexbox por debajo. No es el mismo mecanismo que display: grid de nuestra flota original.

<div class="container">
  <div class="row g-4">
    <div class="col-12 col-md-6">Primer bloque</div>
    <div class="col-12 col-md-6">Segundo bloque</div>
  </div>
</div>

container centra el contenido, agrega espacio lateral y limita su ancho según el tamaño de pantalla. row agrupa las columnas y permite que pasen a otra línea. Cada col-* indica cuántas de doce partes ocupa ese bloque. El contenido real queda dentro de la columna. Puedes usar etiquetas semánticas como section o article si mantienen esa relación.

ClaseFracción del ancho de la filaResultado con bloques iguales
col-1212 / 12 = todo el ancho1 por fila
col-66 / 12 = la mitad2 por fila
col-44 / 12 = un tercio3 por fila
col-33 / 12 = un cuarto4 por fila

De dónde sale el espacio entre columnas

g-4 configura gutters horizontales y verticales de 1.5rem en la escala predeterminada. En horizontal se construyen con relleno en las columnas y márgenes negativos en la fila. Por eso no conviene dejar una row sin un contenedor apropiado: puede sobresalir. gx-* y gy-* permiten variar cada dirección por separado.

No pongas siete artículos sueltos junto a las columnas. Cada bicicleta necesita su propia envoltura col-*. Si un bloque ocupa más espacio del que queda en la fila, pasa a la siguiente; no tiene que completarse una fila de doce antes de cerrar el HTML.
FUNDAMENTO 03

Comprende los breakpoints

Un breakpoint es un ancho a partir del cual se aplica un cambio. Bootstrap trabaja mobile-first: primero define el tamaño pequeño y luego añade reglas para anchos mayores. Los nombres sm o lg se refieren al ancho del viewport en píxeles CSS, no a una marca de celular o a un dispositivo concreto.

PrefijoSe activa desdeEjemplo
Sin prefijo0 pxcol-12
sm576 pxcol-sm-6
md768 pxcol-md-6
lg992 pxcol-lg-4
xl1200 pxcol-xl-3
xxl1400 pxcol-xxl-2
<div class="col-12 col-sm-6 col-lg-4 col-xl-3">
  <!-- Una bicicleta -->
</div>

En este ejemplo el bloque ocupa todo el ancho al principio. Desde 576 px ocupa la mitad. Desde 992 px ocupa un tercio. Desde 1200 px ocupa un cuarto. Una regla sigue aplicándose por encima de su breakpoint hasta que otra la sustituye. A 768 px, como no hay col-md-* en este ejemplo, sigue vigente col-sm-6.

MINI RETO 5 · PASO 01

Crea la página de prueba

Crea la carpeta pruebas dentro de rueda-libre-v1.5. Dentro crea catalogo-bootstrap.html. Este archivo es un laboratorio para comparar: no reemplaza todavía la página de inicio.

<!DOCTYPE html>
<html lang="es">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Prueba de flota | Rueda Libre</title>
  <link rel="stylesheet"
    href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/css/bootstrap.min.css">
</head>
<body>
  <main class="container py-5">
    <h1 class="mb-4">Nuestra flota</h1>
    <div class="row g-4" id="flota">
      <!-- En el siguiente paso van las siete columnas. -->
    </div>
  </main>
  <script
    src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/js/bootstrap.bundle.min.js">
  </script>
</body>
</html>

No enlaces css/styles.css en esta página de prueba. Así demostrarás que la distribución sale de Bootstrap. El enlace CSS va en head; el script va antes de cerrar body. Puedes dividir una etiqueta en varias líneas entre atributos: eso no cambia su funcionamiento.

Comprueba la carga

Abre la página con Live Server. Pulsa F12, abre Network y recarga. Filtra por bootstrap: deben aparecer el CSS y el bundle sin errores. Una respuesta servida desde caché o un 304 puede ser normal; un 404 indica que la ruta está mal. El título debe tener margen inferior y el contenido debe quedar separado de los bordes.

Si todo parece HTML sin estilos, comprueba primero el enlace CSS y la conexión. No intentes arreglar una descarga fallida agregando reglas propias al laboratorio.

MINI RETO 6 · FUNDAMENTO

Aprende a leer las utilidades

Una utilidad suele resolver una propiedad concreta. En vez de crear .espacio-abajo para una sola sección, puedes aplicar mb-4. La notación de espaciado combina la propiedad, el lado, un breakpoint opcional y un valor.

ParteSignificadoEjemplo
m / pmargin / paddingmb-3 / p-3
t / barriba / abajomt-2 / pb-4
s / einicio / final de la dirección de escriturams-2 / pe-3
x / yambos lados horizontales / verticalespx-3 / py-5
md, lg…desde ese ancho en adelantemb-md-0
ValorEspacio por defecto
00
10.25rem
20.5rem
31rem
41.5rem
53rem
autoMargen automático cuando la utilidad lo admite

Con la configuración habitual de 16 px para 1rem, p-3 equivale a 16 px. Si cambia el tamaño raíz, cambia su equivalencia. mb-4 mb-md-0 deja 1.5rem debajo en tamaños pequeños y retira ese margen desde 768 px.

Otras clases que usaremos

fw-bold resalta el peso del texto; fs-5 elige un tamaño de fuente; text-center centra texto; lead destaca un párrafo. bg-warning asigna un fondo y text-dark un texto oscuro. text-bg-dark combina un fondo oscuro con texto claro. Elegir una utilidad de color no reemplaza revisar el contraste.

En Bootstrap 5 usa ms-* y me-* para inicio y final. No copies ml-* o mr-* de ejemplos antiguos. No todos los nombres aceptan un breakpoint: por ejemplo, fs-md-5 no viene incluido como utilidad estándar. Usa las clases que existen.

MINI RETO 6 · PASO 02

Organiza la llamada a la acción

Debajo de los beneficios, todavía dentro de main, agrega una franja con texto y un enlace a reservas. En móvil quedará apilada; desde md sus elementos compartirán una fila.

<section class="p-4 rounded-3 text-bg-dark"
  aria-labelledby="rodar-titulo">
  <div class="d-flex flex-column flex-md-row align-items-center
    justify-content-between gap-3">
    <div>
      <h2 id="rodar-titulo" class="mb-2">¿Listo para rodar?</h2>
      <p class="mb-0">Elige tu bicicleta y prepara tu recorrido.</p>
    </div>
    <img src="../img/logo.svg" alt="" width="80" height="80"
      class="d-none d-md-block">
    <a href="../paginas/reservas.html"
      class="d-inline-block bg-warning text-dark fw-semibold
        px-4 py-3 rounded-3 text-decoration-none">
      Ir a reservas
    </a>
  </div>
</section>

flex-column coloca el eje principal en vertical. flex-md-row lo vuelve horizontal desde 768 px. justify-content-between reparte el espacio sobrante en ese eje; align-items-center centra en el eje cruzado. gap-3 mantiene una separación de 1rem cuando no sobra espacio.

d-none oculta la imagen y la saca de la distribución. d-md-block la muestra desde md. El alt vacío es adecuado porque este logo es decorativo: el nombre del negocio ya está en el contexto. No ocultes con esta técnica información necesaria para reservar.

Por qué el enlace sigue siendo un enlace

Ir a reservas navega a otra página, por eso usamos a. Un button serviría para una acción dentro del contexto actual, como enviar un formulario. Que un enlace tenga fondo y relleno no cambia su función. El aspecto destacado de hoy se consigue con utilidades.

Comprueba y registra

A 767 px la imagen debe estar oculta; a 768 px debe aparecer y la franja pasar a fila. Usa Tab para llegar al enlace. En la bitácora explica cinco clases que consultaste y probaste, y guarda el mini reto en Git.

Qué debes retirar del CSS en este punto

Retira las reglas de .portada, .servicios, .rutas y .flota, incluidas sus variantes dentro de las media queries. De .bici retira display, flex-direction y gap. Retira la regla .bici .boton que se sustituyó por mt-auto y align-self-start. Conserva .bici h3 y .bici p si quieres mantener los márgenes de su contenido.

No elimines aún .layout-tarifas, .layout-reservas ni .fila-campos: las otras páginas todavía dependen de ellas. Comenta esos bloques como pendientes del mini reto 8.

MINI RETO 7 · PASO 04

Resuelve conflictos con DevTools

Si algo no se ve como esperabas, selecciona ese elemento con Inspeccionar. En Styles busca la propiedad en conflicto. Una declaración tachada perdió frente a otra regla; no siempre significa que sea inútil o incorrecta. En Computed revisa el valor que finalmente se aplica y desde dónde viene.

SíntomaQué inspeccionarCorrección razonada
La fila sigue siendo una cuadrícula CSS¿Quedó class="flota row" y .flota con display: grid?Retira flota del marcado y su regla de distribución
Una fila queda centrada y estrecha de más¿Se conservaron contenedor y container juntos?Sustituye contenedor por container; retira la regla anterior cuando no se use
El título usa otra fuente¿Una regla posterior sobrescribe font-family?Mantén la regla agrupada de títulos en styles.css y verifica las fuentes cargadas
Un enlace no cambia de color¿Tiene una utilidad text-* que declara color importante?Retira la utilidad si el color debe venir de la clase de marca

Especificidad y orden con un ejemplo

/* p tiene especificidad 0-0-1 */
p { color: var(--azul-noche); }

/* .bici p tiene especificidad 0-1-1 */
.bici p { color: var(--verde-ruta); }

Si ambas reglas tienen la misma importancia y pertenecen al mismo contexto de cascada, gana .bici p por su mayor especificidad. Para que solo el precio sea verde, evita teñir todos los párrafos y usa la clase precio en el párrafo correspondiente. No resuelvas cada diferencia agregando !important.

La herencia no es otra competencia entre selectores

Un párrafo puede heredar color de body si no recibe otro color. En cambio, background y padding no se heredan de esa forma. Una regla que asigna color directamente al párrafo se aplica antes que el color que habría heredado. Por eso hay que inspeccionar el elemento correcto.

Registra tres conflictos que realmente observes: selector, propiedad, valor ganador y cambio realizado. Los ejemplos de esta página son hipótesis para diagnosticar, no resultados que debas copiar como si hubieran ocurrido.

MINI RETO 8 · PASO 03

Entiende la validación que conservas

La validación nativa la realiza el navegador antes de enviar el formulario. Bootstrap no comprueba la disponibilidad de bicicletas. Cambiar columnas o colores no debe modificar required, pattern, min, max o los nombres de los controles.

CampoRegla del casoCómo se expresa
NombreObligatorio, mínimo 3 caracteresrequired y minlength="3"
Documento6 a 10 dígitostype="text" y pattern="[0-9]{6,10}"
CorreoFormato de correo y obligatoriotype="email" y required
Celular10 dígitos, empieza por 3type="tel" y pattern="3[0-9]{9}"
Fecha1 nov a 31 dic de 2026type="date", min y max

El documento es un identificador, no una cantidad para hacer operaciones: text permite usar un patrón y conservar ceros iniciales. inputmode="numeric" sugiere un teclado, pero no valida. En el patrón [0-9] significa un dígito; {6,10} exige entre seis y diez. type="tel" tampoco valida por sí solo un número colombiano: lo hace el patrón.

for, id y name cumplen funciones distintas

for conecta la etiqueta con el control que tiene ese id. Al hacer clic en el label, ese control recibe foco o cambia su selección. name identifica el dato enviado. Los radios del tipo de bicicleta comparten name para permitir una sola elección. Cada uno conserva un id distinto.

El proyecto mantiene method="post" del caso. Un servidor estático no procesa reservas: después de pasar la validación, el envío puede terminar en 405 o 501. No es una reserva confirmada ni una falla del patrón. No cambies a GET para ocultar esa limitación. Usa datos ficticios.

Cómo leer los números

Si pasas de 180 a 120 líneas de CSS, la reducción de líneas es (180 - 120) / 180 × 100 = 33.3 %. Es un ejemplo de cálculo, no una medición de tu trabajo. No compares una hoja compactada en una línea con otra formateada en muchas. Tampoco sumes las clases del HTML como si fueran líneas de CSS.

Bootstrap no elimina el CSS que ejecuta el navegador: incorpora una hoja externa. La reducción que estás midiendo es de tu hoja propia. Si quieres comparar tiempo de construcción completo, ambas versiones deben haberse construido y cronometrado con un alcance comparable.

CIERRE DEL DÍA

Guarda y publica la versión beta

Después de cada mini reto, comprueba qué cambió y guarda un commit que describa su resultado. Si trabajas con más personas, acuerden quién modifica cada archivo y revisen los cambios antes de integrarlos.

git status
git diff
git add .
git commit -m "Migra tarifas y reservas a Bootstrap"
git push origin main

git status lista cambios y git diff muestra diferencias. add prepara lo que vas a guardar. commit crea la versión local; push la envía al remoto que ya debes tener conectado. Si no existe origin, crea un repositorio vacío en tu cuenta y agrega su URL real con git remote add origin URL. No escribas literalmente URL.

Publica desde tu propio repositorio

En GitHub abre Settings, luego Pages. Elige Deploy from a branch, rama main y carpeta / (root). Guarda la configuración. Cuando la publicación termine, abre la URL que muestra GitHub. No cambies las rutas relativas por rutas de tu disco ni por rutas que empiecen en /: en un sitio de proyecto podrían apuntar fuera de su carpeta.

Revisión en línea

Desde la URL publicada recorre inicio, tarifas, reservas y la página de pruebas. Comprueba imágenes, fuentes y CSS. Si algo funciona localmente pero falla en línea, revisa mayúsculas y minúsculas: img/Rio.svg no es el mismo nombre que img/rio.svg en todos los servidores. Registra la URL real en la bitácora.

Preguntas para explicar con tus palabras
